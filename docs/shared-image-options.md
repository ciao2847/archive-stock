# 整圖多款訂購

在「訂購管理 → IP 訂購頁 → 商品設定」點選「整圖多款上架」。

這是訂購管理內的額外上架方式，可以依商品選用。既有的新增單品、文字批量上架與庫藏商品選取照常使用；同一份訂購頁可以同時包含單品與整圖多款商品。

1. 上傳一張包含全部款式的完整圖片。
2. 填寫商品／作品名稱、國家版本、統一會員價與選填尺寸。
3. 每行輸入一個款式名稱，或點「帶入第1款至第6款」後修改名稱。支援 2 至 50 款。
4. 建立後會自動選入目前訂購頁，再按「儲存商品設定」或「發佈訂購頁」。單價與每人數量上限可在既有商品設定中分款調整。

公開訂購頁將使用完全相同圖片的商品合併顯示，一張完整圖片下列出各款數量。各款同價時只在圖片下方顯示一次統一單價，款式列只顯示名稱與數量。例如第1款 2 張、第2款 3 張，可以一起送出。若既有商品確實有不同單價，則保留各款價格供顧客辨識。零數量款式不送出，停止訂購的款式不能選，原有截止、數量上限、聯絡資料與 Turnstile 驗證沿用現有流程。

系統仍以獨立商品 ID 記錄各款，讓採購數量、付款明細、到貨入庫及包貨核對保留款式名稱。這個入口建立的是預購商品，初始庫存為 0，不會直接扣現貨庫存。若之後替某一款換成獨立圖片，該款會在公開頁獨立顯示。

## 資料庫更新

部署前須套用 `supabase/migrations/20261111115841_shared_image_product_options.sql`，相依於既有商品命名及文字批次建立 migration。此變更不修改既有商品或訂單資料。

- 新 RPC 在同一交易內建立各款並指向同一組主圖／縮圖，沿用既有批次 receipt 與庫藏 RLS。
- 圖片必須由目前帳號上傳。批次失敗會全部回復；同一批重試不會重複建立，也不會覆寫後來修改過的商品圖片。
- 批次請求在瀏覽器分頁的 sessionStorage 暫存，重新整理後可以繼續確認。請求結果不確定時保留圖片，避免誤刪已成功建立的商品圖片。
- Storage 新增 restrictive DELETE policy：只要仍有任一商品參照圖片，就保留該圖片。最後一個參照移除後，原有圖片刪除流程才可清除。這項限制與原有上傳者／管理員權限一起生效。

## 驗證

```bash
npm test
npm run typecheck
npm run lint
npm run build -- --webpack
node tests/browser/shared-image-options.browser.mjs
```

資料庫測試使用 PGlite 執行實際批次與圖片保護 migration，產品建立邊界使用最小 fixture。瀏覽器測試使用本機 mock API，涵蓋 375／768／1440px、共用整圖、混合數量、各款單價、數量上限、停用／截止與斷線後重新整理重試。正式 Supabase Storage 上傳與真實送單仍需在設定好環境變數並套用 migration 後驗收。
