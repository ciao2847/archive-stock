# LINE 訂單查詢文字流程

兩個官方帳號各自查詢綁定庫藏的訂購與已確認配單，沿用現有的
`query_customer_claims_summary`。不需要新增環境變數或資料庫遷移。

1. 只接受完整文字「結帳與查詢」作為查單入口，提示輸入訂購時的 09 開頭十碼手機，
   說明可查詢未結帳與已結帳。舊的「結帳、我要結帳、查單、查詢明細、匯款帳號」等文字不再觸發提示。
2. 直接輸入手機也可以查詢。可使用連字號或空白分段；格式錯誤會收到修正提示。
3. 查詢成功先顯示未結帳筆數／尚欠總額，以及已結帳筆數／已付清總額，
   附「未結帳、已結帳、全部訂單」快速回覆按鈕。
4. 各分類按日期由新到舊，每頁最多五筆，提供上一頁／下一頁。每筆列出確認編號、
   訂購日期、商品、數量、金額與付款狀態。部分付款歸在未結帳，顯示已付與尚欠金額。
5. 只有未結帳清單附上庫藏匯款資料與末五碼回報提醒，不重複附上網站的加入官方 LINE 提醒；已結帳代表款項已清，不表示已出貨。
6. 查無手機紀錄或分類沒有訂單時，明確回覆相應原因。

也支援直接傳送「已結帳 0987654321」、「未結帳 0987654321」、
「全部訂單 0987654321」查看指定分類。純五位數字仍沿用匯款末五碼回報。

快速回覆使用有效期 30 分鐘的加密查詢票證，綁定 LINE 使用者與庫藏，
不依賴單一伺服器的記憶體。票證不包含明文手機，跨使用者／跨庫藏／遭竄改／逾時
都必須重新輸入手機；每次點擊會重新讀取最新付款資料。
手機查詢沿用既有流程，不代表已驗證手機持有人身分。

LINE 單次回覆最多五個訊息，每個文字訊息不超過 5,000 UTF-16 單元。
明細會自動分段；異常大量內容超過單次回覆上限時明確提示聯絡客服。
電腦版不支援快速回覆時，可改用「分類＋手機」的文字方式。

「已匯款、末五碼」仍只回覆由管理者核對，不會自動改為已付清。
回報優先讀取「末五碼／末5碼／後五碼／後5碼」後明確填寫的五位數字，
保留開頭的 0，也接受全形數字。訂單確認編號與電話不作為末五碼來源。
標示未填、位數錯誤或有不同的末五碼時，提示重新提供，不猜測數字。
純五碼與「已匯款 12345」仍可使用。
「人工、客服、真人」不觸發自動回覆。

驗證：

```sh
node --experimental-strip-types --test tests/line-channels.test.mts tests/line-orders.test.mts tests/line-webhook.test.mts
npm run typecheck
```

正式部署完成後，可在兩個官方帳號各自傳送「結帳與查詢」及測試手機，
核對三類訂單、匯款帳號與分頁。測試中不會向真實 LINE 使用者發送訊息。
