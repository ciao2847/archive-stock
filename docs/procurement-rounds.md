# 商品多工藝與分批結單

同一張飯製海報會在一個商品區塊內顯示多種工藝。各工藝仍有自己的商品 ID、數量選擇、現貨庫存及實拍影片；選亮銀龍 2 張、水波紋 3 張時，是同一張訂單中的兩個明細。售價沿用飯製統一價格。

## 每次結單怎麼計算

飯製管理的所選表單、預購管理的所選 IP 表單，都會有「本次結單」區塊。每份表單的批次獨立：

1. 新訂單歸入目前批次，區塊會顯示已付清和未付清的數量。
2. 「結單並產生叫貨單」只納入本批已付款的有效訂單。部分付款仍屬於未付清；有匯款紀錄時，以實際付款合計是否達訂單金額判定，沒有匯款紀錄則接受管理者手動標記「已付全額」。已取消或已刪除的正式訂單排除。
3. 結單保存當時的商品、SKU、IP、工藝、訂購人數、叫貨數量及金額，並開始下一批。未付款或部分付款的訂單自動留到下一批；後續付清後再參與下一次結單。
4. 表單繼續使用原連結接收新訂購。結單不暫停接單，也不清除顧客、付款或包貨紀錄，不會額外扣庫存。
5. 可切換歷史批次查看及下載 CSV。舊批次是結單當時的快照，日後改名稱、價格、付款或刪單，不會自動改寫已產生的叫貨單。結單後若需取消已叫貨數量，應另外核對供應商訂單。

例如本期有亮銀龍 10 張已付清、水波紋 6 張已付清，另有亮銀龍 3 張未付款。結單會產生亮銀龍 10、水波紋 6；下一批留下亮銀龍 3 張，付清前不會列入下一次叫貨。

沒有已付款有效明細時不能結空批。同一次結單重試會回傳原本批次，兩個人同時結單也不會把新批次誤結掉。

## 四項商品數量與批次

訂購管理保留原本的累計統計：訂購人數、總訂購數量、未結清數量、已付款數量（叫貨依據）。新增結單區塊不會取代這四個數字；採購 CSV 仍只匯出全額付款商品與數量。

飯製管理沿用同一套商品卡片，改依「查看批次」選定的批次統計，並顯示 IP、工藝與 SKU。進行中批次的總數包含已付款與未結清訂單，部分付款全部列入未結清；只有有效的全額付款商品可結單與匯出叫貨 CSV。

結單後，已付款商品成為該批不可變更的叫貨快照，因此歷史批次的總訂購數量等於已付款數量、未結清數量為 0。未結清訂單已移到下一批，下一批顯示這些未結清商品及之後新增的訂單，付款後才計入下一次叫貨。歷史快照不會因原訂單後續付款、改名或取消而改變。

若伺服器尚未套用四項統計 migration，飯製進行中批次會明確顯示安裝提示，保留原本的已付款叫貨預覽；不會把未知數量顯示成 0。原有已結單快照可直接換算四項數字。

## 安裝

本次包含新資料庫功能，已安裝的 `20261114140129_fanmade_catalog_stock_and_media.sql` 不需重跑。依序執行以下新檔，再更新前端：

1. [20261115064319_claim_procurement_rounds.sql](../supabase/migrations/20261115064319_claim_procurement_rounds.sql)
2. [20261115064329_fanmade_catalog_groups.sql](../supabase/migrations/20261115064329_fanmade_catalog_groups.sql)
3. [20261117062627_claim_procurement_batch_product_totals.sql](../supabase/migrations/20261117062627_claim_procurement_batch_product_totals.sql)：追加各批四項商品統計；前兩份已安裝時只需執行這份，不必重跑舊 migration。

在 Supabase SQL Editor 貼上各檔完整內容，各執行一次。各份 migration 都以交易執行；本次程式實作不會自行套用正式資料庫或部署正式站。

既有訂購會歸入第一個未結批次，不會在 migration 執行時自動產生叫貨單。舊飯製商品依庫藏、IP、商品名稱及相同原圖片歸組；缺圖片的舊商品各自保留，避免把不同海報誤合。同名但不同圖片仍是不同商品群組。

## 分頁與安全

飯製公開頁先選取 12 個商品群組，再載入每件商品的完整工藝選項。管理頁每頁 24 個商品群組。影片仍按工藝商品 ID 點擊後才載入，庫存預留和包貨維持原有流程。

叫貨批次及明細限目前庫藏的管理者查看，匿名使用者無法存取。結單過程與表單送單以同一份表單的交易鎖劃分前後批次，叫貨快照和未付款移期在同一交易完成。

驗證方式：`npm test` 包含資料庫、API、CSV 測試；`npm run test:fanmade-ui` 驗證同商品多工藝及上架；`npm run test:procurement-ui` 驗證結單、歷史、回應遺失重試與下載，均涵蓋手機、平板和桌面尺寸。資料庫測試使用 PGlite，執行實際 migration、公開送單與包貨函式；沒有操作正式資料。多連線資料庫壓力測試不在這組本機測試範圍。
