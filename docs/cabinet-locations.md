# 櫃子與格位管理

每個庫藏可建立櫃子，設定 1–99 排、每排 1–99 格，每個格位可改名。櫃子沿用固定代碼，格位名稱的修改不影響商品分配。

## 操作

- 點格位查看海報款數與張數。格位可以放多款海報，同款也可分放多格。
- 用 A／B／C 櫃分頁切換，一次只顯示一個櫃子。鍵盤左右鍵、Home、End 也能切換；新建櫃子後會自動選取新櫃。
- 櫃子畫布維持寬高比 2:1，格位依排數與欄數均分寬、高，不水平捲動。3 排 × 11 格會有 33 個真正可選取的格位。小格只顯示排／格編號與張數，完整名稱及編輯／刪除操作集中在詳情面板；手機版面板顯示於下方。
- 可用空格使用虛線，目前選取加深框線，鎖定快速建檔格位使用專案藍色。舊櫃子缺少的座標會標示「尚未建格」，可用「補齊格位」一次補齊；完整櫃子的「增加一欄」則為每排各增加一格。
- 「待整理海報」顯示未分配的實體庫存。批次放入支援搜尋、全選、逐款勾選、加減或輸入數量，範圍不超過未分配張數。
- 「搬移」將來源格的張數轉移至其他格，商品總庫存保持不變。
- 「拆箱快速建檔」新增到貨海報及庫存。儲存後保留國家版本與售價，名稱清空、數量回到 1。圖片可之後在商品編輯補上。
- 鎖定建檔庫位後，即使查看同櫃其他格，也持續建檔到鎖定格。切換櫃子會解除原櫃的鎖定，快速建檔目標同步改成新櫃第一格，保留未儲存的名稱、金額等欄位。取消鎖定即可選其他位置，或先選「待整理」。
- 一般商品入庫可直接從下拉選單選擇櫃子／格位，不必輸入代碼。
- 有海報、舊主庫位關聯或歷史搬移紀錄的格位不能刪除／縮減；空白且無引用的格位可刪除，再用「補齊格位」補回。

## 庫存一致性

`products.stock` 仍是實體庫存總數，`product_location_stocks` 僅記錄其位置分配。批次放入與搬移不增加庫存。舊的商品編輯、搬移及訂單扣庫存仍可使用：主庫位變更會搬移全數；庫存減少時分配張數會同步縮減，以舊主庫位優先、其餘依格位 ID 順序扣除。尚未分配的庫存可能先被扣除，因此售出後仍需按實際取貨位置整理格位。

操作在資料庫交易中鎖定庫藏與商品，超量、跨庫藏或任何一項失敗都會回滾整批。分配表只開放讀取，寫入須經授權 RPC。

## 上線

1. 先套用 `20261008020858_simplify_product_intake.sql`。
2. 套用 `supabase/migrations/20261008062944_cabinet_location_management.sql`。
3. 以 postgres 在 SQL Editor 一次執行整份 `supabase/migrations/20261008073128_switchable_cabinet_grids.sql`。它會保留既有櫃子與自訂格位名稱，清理未命名的佔位格子（格位先留空待後續安排），並按本次需求清除**所有庫藏**的位置分配，保留商品、圖片、庫存及歷史搬移紀錄。首次完成會記錄在私有維護表，重複執行不再清除新入庫的位置。若檢查到商品或庫存被意外改變，整筆更新會回滾。
4. 以 postgres 在 SQL Editor 一次執行整份 `supabase/scripts/verify-cabinet-locations.sql`；成功為 `Success. No rows returned`，測試資料會在區塊內回滾。需有 staff 庫藏與可用的新櫃子代碼。
5. 部署應用。上述正式資料庫更新須另外執行，本機測試通過不表示正式資料庫已清除位置。

```sh
npm run test

npm run build
node tests/browser/location-storage.browser.mjs

```

瀏覽器使用隔離 API fixtures 驗證操作。SQL 遷移及安全檢查另在隔離 PostgreSQL 驗證；不代表正式資料庫已套用。

## 全庫藏重新分配位置

本次重新入庫使用上線步驟中的 `20261008073128_switchable_cabinet_grids.sql` 即可，**不需要再執行舊的重設腳本**。執行後，在庫且有剩餘庫存的海報會回到「待整理海報」，可重新批次放入格位。

`supabase/scripts/reset-all-poster-location-assignments.sql` 留作未來明確要求再次全庫藏重設時使用。它沒有一次性保護，每次執行都會清掉當時的位置分配；結果中的 `remaining_slot_allocations` 應為 0，且回報保留商品數、櫃子數與格位數。
